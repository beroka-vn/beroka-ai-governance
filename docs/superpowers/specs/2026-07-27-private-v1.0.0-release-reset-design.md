# Private v1.0.0 Release Reset Design

**Date:** 2026-07-27
**Target release:** `v1.0.0`

## Goal

Publish the first supported team release as `v1.0.0` while keeping
`beroka-vn/beroka-ai-governance` private. The previous `v1.0.0` and `v1.0.1`
GitHub Releases and tags were unused by the team and were deleted on
2026-07-27. Git commit and branch history remain unchanged.

## Supported onboarding command

The active team documentation uses one authenticated GitHub CLI command:

```bash
gh release download \
  --repo beroka-vn/beroka-ai-governance \
  --pattern bootstrap.sh \
  --output - |
  sh -s -- --client codex --non-interactive
```

Developers replace `codex` with `claude` or `cursor`. `gh` must already be
installed and authenticated for the private repository. When GitHub
authentication is missing, the remediation is:

```bash
gh auth login --hostname github.com --web
```

The GitHub CLI owns its OAuth credentials and may show the provider login URL.
Governance never requests, prints, logs, or stores the OAuth token.

Anonymous `curl` release-asset URLs are not supported while the repository is
private. Active onboarding documentation must not present the old
`releases/latest/download/bootstrap.sh` command.

## Repository changes

- Set the root `VERSION` and active release examples to `v1.0.0`.
- Replace the active anonymous `curl` launcher in `README.md`, `handbook.md`,
  and `PACKAGE-DESIGN.md` with the authenticated `gh release download`
  launcher.
- Document `gh` installation/authentication as a prerequisite for private
  release download.
- Update release assertions in the existing shell tests.
- Keep historical specs and plans unchanged.
- Do not change connector setup, routing, bootstrap behavior, or OAuth
  ownership.

## Release sequence

1. Implement and review the repository changes through a pull request.
2. After the human merges that exact pull request, verify its merge commit
   contains `VERSION=v1.0.0`.
3. Create a new annotated `v1.0.0` tag at that exact merge commit without
   force-pushing or rewriting Git history.
4. Render `release/bootstrap.sh.in` with the exact tag and merge commit.
5. Run the existing shell tests and isolated local pilots before publication.
6. Push the tag and publish a stable GitHub Release with `bootstrap.sh`.
7. Download the published asset through `gh release download`, then execute it
   with temporary HOME/XDG directories and no Atlassian credentials.
8. Verify the expected fail-closed `ATLASSIAN_AUTH_REQUIRED` result and the
   exact selected-client remediation.
9. Verify `v1.0.0` is the only stable Release/tag.

Published tags are immutable after this reset. Any later change uses a new
SemVer version.

## Acceptance criteria

- Active docs show only the authenticated private-repository launcher.
- `VERSION` and active examples select `v1.0.0`.
- Existing tests pass without real Atlassian credentials.
- The published asset embeds the exact annotated tag and merge commit.
- An isolated Codex pilot installs and registers the repository, then fails
  closed with `ATLASSIAN_AUTH_REQUIRED` when client OAuth is absent.
- No developer API token is accepted, printed, logged, or stored.
- Git history and historical design/plan documents are preserved.
