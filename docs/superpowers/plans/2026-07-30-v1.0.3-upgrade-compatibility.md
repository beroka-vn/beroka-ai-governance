# v1.0.3 Upgrade Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore the supported one-command upgrade from immutable `v1.0.1` installations while keeping `runtime/rules/work-items.md` mandatory from `v1.0.2` onward.

**Architecture:** Keep the shared release validator as the single enforcement point. Reuse `semver_not_older` to select the historical manifest, then exercise the real bootstrap transaction with annotated local release tags.

**Tech Stack:** POSIX shell, Git, existing shell test suite

## Global Constraints

- `runtime/rules/work-items.md` is optional only for `v1.0.0` and `v1.0.1`.
- `runtime/rules/work-items.md` is required for `v1.0.2` and every later version.
- Do not add dependencies, a second SemVer parser, or a release-manifest abstraction.
- Do not alter the published `v1.0.1` or `v1.0.2` tags or releases.
- Do not merge or publish `v1.0.3` without explicit approval for the reviewed commit.

### Task 1: Version-aware release validation

**Files:**
- Modify: `tests/bootstrap.sh`
- Modify: `bin/beroka-governance`

**Interfaces:**
- Consumes: `validate_release_checkout CHECKOUT VERSION` and `semver_not_older CURRENT TARGET`.
- Produces: historical validation that permits only pre-`v1.0.2` releases to omit `runtime/rules/work-items.md`.

- [ ] **Step 1: Write the failing integration regression**

Build annotated local `v1.0.1`, invalid `v1.0.2`, and valid `v1.0.3`
fixtures in `tests/bootstrap.sh`. Assert that the real bootstrap command:

```sh
$CLI bootstrap "$repo" --client codex \
  --version v1.0.1 --non-interactive
$CLI bootstrap "$repo" --client codex \
  --version v1.0.3 --upgrade --non-interactive
```

activates the exact `v1.0.3` commit, while direct installation of the
`v1.0.2` fixture without `runtime/rules/work-items.md` returns:

```text
Result: GOVERNANCE_NOT_READY
Missing release file: runtime/rules/work-items.md
```

- [ ] **Step 2: Run the regression to verify RED**

Run:

```bash
sh tests/bootstrap.sh
```

Expected: FAIL during the `v1.0.1` install with the same missing-file error
reported by the developer.

- [ ] **Step 3: Implement the minimum version floor**

Remove `runtime/rules/work-items.md` from the unconditional routing-file loop
and add this single conditional check in `validate_release_checkout`:

```sh
if semver_not_older v1.0.2 "$vrc_version"; then
  assert_release_file "$vrc_checkout" runtime/rules/work-items.md
fi
```

- [ ] **Step 4: Run the regression to verify GREEN**

Run:

```bash
sh tests/bootstrap.sh
```

Expected: `Bootstrap onboarding tests: PASS`.

- [ ] **Step 5: Commit the tested fix**

```bash
git add bin/beroka-governance tests/bootstrap.sh
git commit -m "fix: validate historical release manifests"
```
