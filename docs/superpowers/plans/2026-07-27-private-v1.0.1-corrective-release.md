# Private v1.0.1 Corrective Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the reviewed private-onboarding corrections as immutable patch release `v1.0.1` without moving or deleting `v1.0.0`.

**Architecture:** Keep the reviewed fail-safe launcher contract and bootstrap implementation unchanged. Update only the active release identity and release tests, then publish the exact human-merged commit as a new annotated tag.

**Tech Stack:** POSIX shell, Git, GitHub CLI

## Global Constraints

- Keep `v1.0.0` Release/tag unchanged and mark it superseded for onboarding.
- Set the current supported team release to `v1.0.1`.
- Preserve the reviewed temporary-file Quick start block exactly.
- Never force-push, move, replace, or delete a published tag.
- Never request, print, copy, log, or store developer API/OAuth tokens.
- Keep OAuth owned by GitHub CLI, the selected client, and the OS keyring.
- Never stage, edit, or delete root `.beroka-governance.lock` or `AGENTS.md`.

### Task 3: Publish v1.0.1

**Files:**
- Read: exact merged `VERSION`
- Read: exact merged `release/bootstrap.sh.in`
- Create outside repository: temporary candidate asset and pilot environments

**Interfaces:**
- Consumes: exact human-merged Task 2 PR
- Produces: stable/latest `v1.0.1` while preserving `v1.0.0`

- [ ] **Step 1: Candidate gates**

Resolve the PR's exact merge commit and verify `VERSION=v1.0.1`. Verify remote
`v1.0.1` is absent and remote `v1.0.0` retains its current annotated identity.
Run the full shell suite from an exact detached checkout. Render and syntax
check the candidate asset.

- [ ] **Step 2: Isolated unpublished pilot**

Create a local annotated candidate `v1.0.1` at the exact merge and use a
temporary URL rewrite, HOME/XDG/CODEX/bin, and no Atlassian credentials. Expect
exactly one `ATLASSIAN_AUTH_REQUIRED` and remediation
`codex mcp login atlassian`, with installation/registration pinned to the exact
merge.

- [ ] **Step 3: Publish**

Run a fresh non-interactive `github-write` preflight immediately before pushing
the tag and another before creating the stable/latest GitHub Release. Never
force. Stop on partial failure without deleting any release or tag.

- [ ] **Step 4: Published Quick start pilot and final verification**

Execute the exact active Quick start block from the merged README with temporary
HOME/XDG/CODEX/bin, existing GitHub OAuth only through explicit
`GH_CONFIG_DIR`, and no Atlassian credentials. Verify the asset hash, embedded
version/commit, exact fail-closed outcome, and final remote state:

- `v1.0.0` remains unchanged;
- `v1.0.1` is stable/latest and peels to the exact merge;
- `v1.0.1` has exactly one validated `bootstrap.sh` asset.
